# کنترل به‌روزرسانی سامانه امید

## راه‌اندازی اولیه

۱. کد این شاخه را دریافت کنید. جدول جدید `MaintenanceSettings` با Migration زیر ساخته می‌شود؛ حالت اولیه **خاموش** است و اطلاعات قبلی سامانه تغییر نمی‌کند:

```powershell
Update-Database -Project VisitorManagment.DataLayer -StartupProject VisitorManagment.Web
```

یا در صورت نصب ابزار dotnet-ef از ریشه Solution:

```bash
dotnet ef database update --project VisitorManagment.DataLayer --startup-project VisitorManagment.Web
```

شناسه Migration: `20261031160000_AddMaintenanceMode`.
Migration باید پیش از شروع استفاده از نسخه جدید روی دیتابیس اعمال شود. نیازی به اجرای مجدد آن برای هر بار روشن/خاموش کردن قابلیت نیست.

۲. در `VisitorManagment.Web/appsettings.json` حساب اختصاصی توسعه در `Maintenance:DeveloperUsernames` قرار دارد. مقدار اولیه `95003599`، همان حساب اختصاصی توسعه/پشتیبانی موجود در کد سامانه است. در صورت متفاوت‌بودن حساب برنامه‌نویس، پیش از پابلیش این مقدار را اصلاح کنید. این فهرست، رمز عبور یا امکان ورود جداگانه ایجاد نمی‌کند؛ حساب باید در دیتابیس فعال باشد و با ورود معمول احراز هویت کند. نقش مدیر یا Permission به‌تنهایی این دسترسی را نمی‌دهد. کاربران impersonation هم استثنا ندارند.

۳. نسخه جدید را پابلیش کنید. با حساب اختصاصی وارد شوید؛ در نوار بالای سامانه، آیکن تنظیمات به صفحه `/Developer/Maintenance` می‌رود. این صفحه مستقیماً نیز قابل بازکردن است و مجوزش در GET و POST کنترل می‌شود.

## استفاده

- برای توقف، گزینه «فعال‌بودن حالت به‌روزرسانی» را روشن، پیام را وارد و تنظیمات را ذخیره کنید.
- کاربر عادی به صفحه `/UpdateSamane` می‌رود. POST، Ajax و مذاکره اتصال جدید SignalR با HTTP 503 رد می‌شوند و عملیات اجرایی برنامه فراخوانی نمی‌شود.
- فراخوانی‌های اتصال‌های SignalR موجود هم پیش از هر عملیات بررسی و در حالت توقف قطع می‌شوند. صفحات دارای پوسته مشترک با اعلان حضور آنلاین و بررسی دوره‌ای (هر ۵ ثانیه در تب فعال) به صفحه به‌روزرسانی منتقل می‌شوند؛ خروج از صفحه تماس، رسانه مرورگر را نیز متوقف می‌کند. این کنترل دوره‌ای ممکن است در تب پس‌زمینه طبق محدودیت مرورگر دیرتر اجرا شود؛ کنترل سمت سرور مستقل از آن است.
- فقط حساب اختصاصی می‌تواند هنگام توقف از صفحات و عملیات برنامه استفاده کند.
- برای بازگشت، در همان صفحه گزینه را خاموش و ذخیره کنید. وضعیت در دیتابیس ماندگار است؛ خاموش/روشن‌کردن آن ری‌استارت و پابلیش نمی‌خواهد.
- اگر از حساب خارج شدید، از `/Index` وارد شوید و دوباره `/Developer/Maintenance` را باز کنید. مسیرهای ورود، کپچا، خروج، تغییر اجباری رمز و بازگشت از impersonation محلی مسدود نمی‌شوند؛ کنترل دسترسی داخلی آن‌ها برقرار است.
- پیام به‌صورت متن توسط Razor نمایش داده می‌شود و HTML قابل اجرا نیست. POST کنترل از اعتبارسنجی ضدجعل پیش‌فرض Razor Pages استفاده می‌کند. شماره Revision جلوی بازنویسی ناخواسته تنظیمات توسط یک تب قدیمی را می‌گیرد. آخرین تغییر، زمان UTC و شناسه کاربر در دیتابیس ثبت می‌شود.

این قابلیت به بالا بودن خود برنامه و دسترسی به دیتابیس نیاز دارد و جایگزین پنل مدیریت سرور هنگام خرابی کامل برنامه نیست. درخواست‌هایی که پیش از فعال‌سازی شروع به اجرا کرده‌اند خودکار Rollback نمی‌شوند. فایل‌های استاتیک مثل CSS/تصاویر از middleware عبور نمی‌کنند و برای نمایش صفحه توقف در دسترس می‌مانند.

## آزمون‌ها

آزمون‌های متمرکز، فایل‌های واقعی سرویس، middleware، Hub filter و PageModel را لینک می‌کنند و از .NET 5 و EF Core 5.0.3 InMemory استفاده می‌کنند؛ اجرای آن‌ها به SQL Server نیاز ندارد:

```bash
dotnet run --project tests/MaintenanceMode/MaintenanceMode.Tests.csproj
```

آزمون‌ها مجوز حساب توسعه، رد مدیر عادی و impersonation، ماندگاری وضعیت بین scopeها، رقابت تب‌ها، محدودیت HTTP، مسیرهای بازیابی، قطع عملیات SignalR، ذخیره فرم کنترل و حالت اولیه Migration را بررسی می‌کنند. این آزمون‌ها جای Build کامل برنامه، تست مرورگر و آزمون SQL Server در محیط نصب را نمی‌گیرند.

بررسی رفتار اسکریپت انتقال صفحات باز بدون نیاز به مرورگر:

```bash
node tests/MaintenanceMode/maintenance-client.test.js
```
